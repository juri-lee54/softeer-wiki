# RDD API

Spark의 가장 기본적인 분산 데이터 처리 추상화

ataFrame/SQL API보다 저수준이라 더 유연하지만, 최적화(Catalyst optimizer 등)는 부족

## RDD
: 분산된 불변(immutable) 데이터 컬렉션. 여러 노드에 나뉘어 저장되고, 병렬로 처리
- "Resilient"(회복력 있는) 이유: 각 파티션이 어떻게 만들어졌는지(lineage, 계보)를 기억하고 있어서, 노드 장애가 나도 해당 파티션만 재계산해서 복구할 수 있음

<br>

### Transformation
: 새로운 RDD를 "정의"만 함. 실제 계산은 안 일어남 (lazy evaluation)

```python
parsed_rdd = raw_rdd.filter(lambda x: x is not None)   # filter
cleaned_rdd = parsed_rdd.filter(is_valid)               # filter
daily_rdd = cleaned_rdd.map(to_daily_kv).reduceByKey(sum_daily_kv)  # map, reduceByKey
```

<br>

- map: 각 원소를 변환 (parse_parquet_row, to_daily_kv 등에 사용)
- filter: 조건에 맞는 원소만 남김
- reduceByKey: key가 같은 값들끼리 결합 함수(sum_daily_kv)로 합침 — SQL의 GROUP BY + SUM과 비슷
- union: 두 RDD를 합침 (parquet RDD + csv RDD 합칠 때 사용)

<br>

> 이 코드에서 Transformation은 실제로 실행되지 않고 계획만 세워짐
> 실행은 action이 호출될 때 트리거 됨

<br>

### Action
: 실제 계산을 실행하고 결과를 driver로 가져오거나 저장함

```python
total_trips = cleaned_rdd.count()                       # count
total_revenue = cleaned_rdd.map(...).sum()               # sum
avg_distance = cleaned_rdd.map(...).mean()               # mean
daily_rdd.sortByKey().collect()                          # collect
```
<br>

- count(), sum(), mean(): 집계 결과를 숫자 하나로 반환
- collect(): RDD의 모든 원소를 driver 메모리로 가져옴
  - 데이터가 크면 driver가 터질 수 있음. reduceByKey 등으로 이미 줄어든 결과에서 사용


<br>

**lazy evaluation이 중요한 이유**

```python
cleaned_rdd.cache()
```
cleaned_rdd는 count(), sum(), mean(), reduceByKey() 등 여러 액션에서 재사용됨

RDD는 기본적으로 action이 호출될 때마다 lineage를 처음부터 다시 계산하기 때문에, cache()(또는 persist())가 없으면 파일을 매번 다시 읽고 파싱하게 됨

cashe()로 메모리에 고정해두면 첫 action에서만 계산하고 이후에는 재 사용


<br>

### Key-Value RDD 패턴
```python
def to_daily_kv(record):
    return (record.pickup_date, (record.fare_amount, record.trip_distance, 1))
```

(key, value) 튜플 형태의 RDD를 만들면 reduceByKey, sortByKey, groupByKey 같은 pair RDD 전용 연산을 사용할 수 있음

여기선 날짜를 key로, (요금, 거리, 카운트) 튜플을 value로 묶어서 날짜별 집계를 구현함


<br>

### RDD API vs DataFrame API
| | RDD | DataFrame |
|---|---|---|
| 최적화 | 없음 (직접 짜야 함) | Catalyst optimizer 자동 적용 |
| 타입 안정성 | Python 객체 그대로 (namedtuple 등) | 스키마 기반 |
| 용도 | 세밀한 제어가 필요할 때, 비정형/커스텀 파싱 | 대부분의 일반적인 정형 데이터 처리 |

<br>

## RDD 문법

### RDD 생성

(1) 이미 있는 python 컬렉션에서 만들기 : **`parallelize`**

```python
data = [1, 2, 3, 4, 5]
rdd = sc.parallelize(data)
```

이 코드에서도 사용됨:
```python
sc.parallelize(summary_lines)  # 리스트를 RDD로 변환
```

<br>

(2) 외부 파일에서 만들기: **`textFile`**
```python
rdd = sc.textFile("path/to/file.csv")          # 파일 하나
rdd = sc.textFile("path1.csv,path2.csv")       # 여러 파일 (콤마로 구분)
rdd = sc.textFile("path/to/dir/*.csv")         # 와일드카드
```

한 줄(line)이 문자열 하나의 원소가 됨
```python
csv_rdd = sc.textFile(",".join(csv_path))
```

<br>

(3) DataFrame에서 RDD로 변환 : **`.rdd`**

```python
df = spark.read.parquet("file.parquet")
rdd = df.rdd   # Row 객체들의 RDD
```

이 코드에서:
```python
pq_rdd = spark.read.parquet(*parquet_path).rdd
```
DataFrame은 최적화된 정형 API지만, `.rdd`를 붙이면 저수준 RDD로 만들 수 있음

<br>

(4) 기존 RDD를 변환해서 새 RDD 만들기
```python
new_rdd = old_rdd.map(some_function)
```
`parallelize`나 `textFile`으로 시작하고, 이후는 계속 transformation으로 이어지는 구조를 많이 사용



### RDD에 원소 담기

RDD는 Python 객체를 그대로 담을 수 있음. 

`namedtuple`을 사용
```python
from collections import namedtuple
TripRecord = namedtuple("TripRecord", ["pickup_dt", "dropoff_dt", ...])

rdd.map(lambda row: TripRecord(pickup_dt=..., ...))
```
원소를 `record.pickup_dt`, `record.fare_amount`처럼 필드명으로 접근 가능해짐

인덱스(`record[0]`)보다 가독성이 좋음. 

딕셔너리, 튜플, 커스텀 클래스도 다 담을 수 있음

<br>

### 자주 쓰는 Transformation

```python
rdd.map(func)          # 원소 하나 -> 원소 하나 변환
rdd.filter(func)       # func가 True인 것만 남김 (func는 True/False 반환해야 함)
rdd.flatMap(func)      # 원소 하나 -> 여러 원소로 펼침 (예: 문장 -> 단어 리스트)
rdd.union(other_rdd)   # 두 RDD 합치기
rdd.distinct()         # 중복 제거
rdd.sortByKey()        # (key, value) RDD를 key 기준 정렬
```

<br>

**Pair RDD 전용** (`(key, value)` 형태일 때만):
```python
rdd.reduceByKey(func)     # 같은 key끼리 func로 병합 (func는 (v1, v2) -> v 형태)
rdd.groupByKey()          # 같은 key끼리 묶기 (메모리 부담 커서 reduceByKey 선호)
rdd.mapValues(func)       # value만 변환, key는 그대로
```

<br>

미션에서는 다음과 같이 사용
```python
def to_daily_kv(record):
    return (record.pickup_date, (record.fare_amount, record.trip_distance, 1))

def sum_daily_kv(a, b):
    return (a[0] + b[0], a[1] + b[1], a[2] + b[2])

daily_rdd = cleaned_rdd.map(to_daily_kv).reduceByKey(sum_daily_kv)
```
→ `map`으로 `(날짜, (요금, 거리, 1))` 쌍을 만들고, `reduceByKey`로 같은 날짜끼리 튜플을 원소별로 더함.


<br>

### 자주 쓰는 Action

```python
rdd.collect()      # 모든 원소를 driver로 가져옴
rdd.count()        # 원소 개수
rdd.take(n)        # 앞에서 n개만 가져옴 
rdd.first()         # 첫 원소 하나
rdd.sum()          # 숫자 RDD의 합
rdd.mean()         # 숫자 RDD의 평균
rdd.max() / .min() # 최댓값/최솟값
rdd.saveAsTextFile(path)  # 파일로 저장 (파티션별로 나뉘어 저장됨)
```

<br>

미션에서는 다음과 같이 사용

```python
total_trips = cleaned_rdd.count()
total_revenue = cleaned_rdd.map(lambda r: r.fare_amount).sum()
avg_distance = cleaned_rdd.map(lambda r: r.trip_distance).mean()
```
→ 이 세 줄이 실행되는 순간 실제로 Spark가 파일을 읽고 파싱하고 필터링하는 전체 파이프라인이 돌아감

<br>

### action을 하나로 합치기 : reduce()
```python
total_trips = cleaned_rdd.count()
total_revenue = cleaned_rdd.map(lambda r: r.fare_amount).sum()
avg_distance = cleaned_rdd.map(lambda r: r.trip_distance).mean()
```
-> → count(), sum(), mean()은 각각 별도의 action이라 Spark Job이 3개 생김

캐싱을 해줬어도 Job이 3번 스케줄링되는 오버헤드는 남음

<br>

```python
fare_sum_total, distance_sum_total, total_trips = cleaned_rdd.map(
    lambda r: (r.fare_amount, r.trip_distance, 1)
).reduce(lambda a, b: (a[0] + b[0], a[1] + b[1], a[2] + b[2]))
```

reduce(func)는 RDD의 모든 원소를 func로 하나의 값이 될 때까지 짝지어 병합하는 action

reduceByKey가 key별로 병합한다면, reduce는 RDD 전체를 하나로 병합함

여기선 (fare, distance, count) 튜플 하나로 매출합·거리합·건수를 동시에 계산해서, Job 3개를 Job 1개로 줄임

```python
# reduce 기본 개념
rdd.reduce(lambda a, b: a + b)   # 리스트 [1,2,3,4] -> 10
```

<br>

### collect() 후 Python 내장 함수 처리
sortByKey() vs collect() 후 sorted() — RDD 전용 연산(분산 정렬)과 로컬 연산의 트레이드오프

<br>

이전에는 다음과 같이 작성했음

```python
daily_rdd.sortByKey().collect()
```

sortByKey()는 RDD 자체의 분산 정렬 연산임

내부적으로 파티션 경계를 샘플링하는 Job + 셔플 정렬 Job이 추가로 발생하게 됨

<br>

이번에는 날짜(key)가 93개뿐인 아주 작은 결과라서, 굳이 분산 정렬(sortByKey)을 쓰는 대신 collect()로 다 가져온 뒤 Python의 sorted()로 정렬했음

```python
daily_sorted = sorted(daily_rdd.collect())
```

<br>

### 캐싱 

```python
rdd.cache()       # 메모리에 저장 (persist(MEMORY_ONLY)와 동일)
rdd.persist(storage_level)  # 메모리/디스크 등 저장 위치 지정 가능
rdd.unpersist()      # 캐시 해제
```
 여러 액션에서 재사용되는 RDD는 캐싱
